# Demonstration Coding Standards

Replace these sample standards with your project's requirements when adapting
the workflow.

- Follow the project's language, naming, formatting, and test conventions.
- Keep functions focused and use descriptive names. Add types where the
  language and project convention support them.
- Use the standard library and existing dependencies before adding packages.
- Validate external inputs at the boundary and report failures explicitly.
- Cover the requested behavior and edge cases with deterministic local tests.
  Do not depend on live services or model calls for this exercise.
- Keep changes within the requested scope and preserve unrelated user work.
- Report changed files, exact validation commands, results, and unresolved
  limitations so the next node can use the saved report as its handoff.
